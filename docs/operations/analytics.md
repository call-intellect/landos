## Обязательные атрибуты каждого сигнала

Любой сигнал (метрика/лог/трейс/ошибка) несёт эти атрибуты — иначе его нельзя отфильтровать и сшить:

| Атрибут | Значения | Зачем |
|---|---|---|
| **`deployment.environment`** (ОБЯЗАТЕЛЬНЫЙ) | `dev` / `preview` / `prod` | Разделить прод от стендов (см. `stands-and-preview-envs.md`); без него аналитика стендов травит прод-метрики |
| `service.name` | имя сервиса | Какой компонент породил сигнал |
| `service.version` | git SHA / release-тег | Связать сигнал с релизом (см. `prod-deploy-log.md` release-теги) |
| `<tenant-attr>` | id клиента/tenant | Разрез по клиенту (для мульти-tenant) |

## Semantic conventions — единые имена атрибутов

<!--
Как заполнять: ОДНО каноническое имя на сущность во ВСЕХ сигналах. Заведи здесь словарь и не расходись
(`user.id`, не вперемешку `userId`/`user`/`uid`). Стиль — стабильные namespaced-имена (`область.поле`).
-->

| Сущность | Каноническое имя атрибута | НЕ использовать |
|---|---|---|
| Пользователь | `user.id` | `userId`, `uid`, `user` |
| Клиент/tenant | `tenant.id` | `orgId`, `tenant` |
| Запрос | `request.id` | `reqId`, `traceId` (у трейса своё) |
| Результат операции | `outcome` (`ok`/`error`) | `status`, `success` |

## Что замеряем (стартовый набор)

<!-- Как заполнять: минимум метрик, без которых прод слеп. Замени примеры на реальные. -->

- **Здоровье:** доступность health-эндпоинта, время старта.
- **Трафик:** RPS по эндпоинтам, латентность (p50/p95/p99).
- **Ошибки:** rate ошибок по классам (см. `error-handling.md`).
- **Очереди/воркеры:** глубина очереди, время обработки job, доля падений.
- **Бизнес-сигналы:** ключевые события продукта (подставь свои — регистрации, конверсии, единицы созданного контента).
- **Стоимость** (если есть платные внешние вызовы): расход на запрос/tenant.

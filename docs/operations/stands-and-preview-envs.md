> Стенд = временная изолированная копия приложения под ветку/PR для приёмки фичи глазами до мержа.

## Зачем стенды

- **Приёмка глазами до мержа.** Владелец/QA открывает фичу в браузере на реальном (пусть и временном) окружении, а не по описанию.
- **Изоляция.** Ломающая ветка не задевает прод и чужие ветки.
- **Дёшево создать и снести.** Эфемерность — свойство, а не ручная уборка.

## Модель: per-branch / per-PR эфемерные стенды

<!-- Как заполнять: опиши свою модель. Ниже — каноничная (стиль эфемерных preview-окружений). -->

- **Один PR → один стенд.** Стенд поднимается при открытии PR (или по метке), живёт пока PR открыт.
- **Namespacing.** Ресурсы стенда изолированы уникальным префиксом/неймспейсом от `pr-<номер>` (своя схема/база данных, свой поддомен `pr-<номер>.<preview-domain>`, свои имена очередей/бакетов). Два стенда никогда не делят состояние.
- **АВТО-teardown.** При мерже/закрытии PR стенд и ВСЕ его ресурсы (контейнеры, схема БД, бакет, DNS-запись) удаляются автоматически. Ручной уборки быть не должно.
- **TTL-предохранитель.** Дополнительно — авто-снос по простою (например > N дней без активности), чтобы забытый висящий стенд не жил вечно.

## ⚠️ Правило: не плодить склад забытых стендов

Тот же принцип, что Ship-On для флагов: **временное не должно становиться постоянным по недосмотру**. Стенд, который «поднял и забыл», — это утечка ресурсов и источник ложных ссылок. Поэтому:
- teardown автоматический и по умолчанию, а не «когда вспомним»;
- нет «долгоживущих ручных стендов» без владельца и срока;
- список активных стендов виден одной командой (аудит ниже).

## Как поднять / погасить

<!-- Как заполнять: замени на реальные команды своего оркестратора (compose profile / k8s namespace / PaaS preview). -->

```bash
# Поднять стенд под ветку/PR
{{RUNTIME_EXEC}} <spin-up-preview> --ref <branch|pr-number>

# Список активных стендов (аудит — не забыт ли кто)
{{RUNTIME_EXEC}} <list-previews>

# Погасить стенд (обычно авто при закрытии PR; ручной снос — тем же входом)
{{RUNTIME_EXEC}} <tear-down-preview> --ref <branch|pr-number>
```

## Данные на стенде

<!-- Как заполнять: чем наполнять стенд. Правило — НИКОГДА не прод-данными без анонимизации; лучше синтетический baseline + сиды. -->

- **Не прод-данные.** Стенд наполняется синтетическим baseline + сидами, а не боевым дампом (приватность + скорость).
- Помечай окружение атрибутом `deployment.environment=preview` в логах/метриках (см. `analytics.md`), чтобы данные стендов не смешивались с прод-аналитикой.

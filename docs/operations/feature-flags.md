> **Правило Ship-On: выкатываем ВКЛючённым.**
> Готовая фича идёт в прод СРАЗУ включённой. «Дефолт OFF, владелец включит потом» и фаза «понаблюдаем → включим» — **запрещены**: не готова включиться — значит не готова к выкату. Это не плодит склад забытого выключенного функционала.
>
> Допустимы ровно два вида флагов: **аварийный рубильник (A)** — фича работает (ON), рубильник только для экстренного выключения при инциденте; и **решение владельца (C)** — изменение, необратимо меняющее что видят/могут люди или тратящее/блокирующее деньги, выкатывается только вместе с заданным владельцем параметром.

## Как читать типы

| Значок | Тип | Кто и когда трогает |
|---|---|---|
| 🔴 **A — аварийный рубильник** (kill-switch) | Фича РАБОТАЕТ (ON). Рубильник существует только чтобы экстренно выключить при аварии. | Никто в обычной жизни. Только дежурный при инциденте. **Владельца не касается.** |
| 🟢 **C — решение владельца** | Нельзя включить «просто так» — нужен бизнес-параметр (сумма лимита, матрица «кто кого видит»). | **Только владелец.** Каждый такой флаг — с явным вопросом ниже. |
| 💳 **Т — тарифный** | Включается по продаже, отдельно для каждого клиента/tenant. | Продажи / админ, точечно по клиенту. |
| ⚪ **Долг** | Выкачено выключенным по СТАРОМУ правилу (до Ship-On). Разовый разбор: включить готовое или признать незрелым. | Разобрать один раз, дальше по Ship-On такого не появляется. |

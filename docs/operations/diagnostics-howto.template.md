Диагностические harness'ы из разбора «<симптом инцидента>» (YYYY-MM-DD).
Оба — **read-only / локальные**, в прод-конвейер (STEPS/cron/воркеры) не входят, на проде ничего не пишут.

## 1. Детерминированный replay бага

<!--
Как заполнять: harness, который берёт РЕАЛЬНЫЙ вход (захваченный из прод-журнала) и прогоняет его через НАСТОЯЩУЮ
логику дважды — «как сейчас» и «с фиксом» — печатая расхождение. Это регрессионный инвариант: пока
«текущая = баг И фикс = ожидание», корень закрыт; иначе exit ≠ 0.
-->

Прогоняет реальный кейс через настоящую логику и сравнивает «текущее поведение» с «поведением после фикса».

```bash
{{RUNTIME_EXEC}} <replay-script>
# Ожидаемо: текущая=<баг>, фикс=<ожидание> → PASS
```

Инвариант: пока `текущая=<баг> И фикс=<ожидание>` — корень закрыт. `exit 1`, если инвариант сломан.

## 2. Доказательный A/B двух вариантов

<!--
Как заполнять: harness сравнивает два варианта (две модели / два алгоритма / два конфига) на РЕАЛЬНОМ входе,
захваченном из прод-журнала. Выдаёт объективные метрики (корректность, объём результата, стоимость, латентность).
Явно подчеркни: это РУЧНОЙ инструмент, боевой выбор уже сделан — harness лишь перепроверяет по запросу.
-->

> **Это РУЧНОЙ разовый инструмент инженера, НЕ часть прод-конвейера.** Боевой выбор уже сделан в коде; harness нужен лишь чтобы ВРУЧНУЮ, по запросу, перепроверить «вариант A vs вариант B» на реальном входе.

### Шаг 1 — захватить реальный вход
```bash
{{RUNTIME_EXEC}} <capture-script> <id> > ab-input.json
```

### Шаг 2 — прогнать A/B
```bash
AB_VARIANTS="<A>,<B>" \
AB_INPUT_FILE=ab-input.json \
AB_REPEATS=3 \
{{RUNTIME_EXEC}} <ab-script>
```

### Переменные окружения

| Переменная | Дефолт | Назначение |
|---|---|---|
| `AB_VARIANTS` | `<A>,<B>` | сравниваемые варианты через запятую |
| `AB_INPUT_FILE` | `ab-input.json` | захваченный реальный вход |
| `AB_REPEATS` | `3` | прогонов на вариант (оценить разброс) |

**Вывод по разбору (заполнить после прогона):** <какой вариант выиграл и по какой метрике; какой фикс реально лечит симптом>.

# .claude/hooks

Хуки Claude Code для этого проекта. Все — чистый Python (stdlib), без внешних
зависимостей. Каждый читает `tool_input` из stdin (JSON) и завершается кодом
выхода: `0` — пропустить, `2` — заблокировать/предупредить (для PreToolUse `2`
блокирует вызов инструмента).

## Инвариант

**Хук активен ТОЛЬКО если прописан в `.claude/settings.json`.** Файл в этой
папке сам по себе ничего не включает — это просто исполняемый скрипт. Ссылка на
него в `settings.json` (`hooks.<Event>[].hooks[].command`) — единственное, что
его активирует. Добавил файл, но не прописал — он не работает. Удалил ссылку —
хук выключен, файл можно оставить.

## Хуки

| Файл | Событие / matcher | Что делает | Режим |
|---|---|---|---|
| `pre-bash-guard.py` | PreToolUse · `Bash` | Блокирует опасные bash-команды: `git push` в защищённую ветку (`PROTECTED_BRANCHES`, дефолт `[main, master]`), `rm -rf /` и `/*`, `DROP TABLE`. | BLOCK (exit 2) |
| `post-push-reflection.py` | PostToolUse · `Bash` | После реального `git push` печатает чек-лист завершения работы (обнови docs при изменении логики → запиши рефлексию → обнови deploy-log → выдай diff деплой-шагов). Пропускает `--dry-run` и коммиты, которые сами и есть рефлексия. | REMIND (exit 0) |
| `check-no-narrative-comments.py` | PostToolUse · `Edit\|Write` | Сканирует добавляемый код (не `.md`); если появились нарративные комментарии (объяснительная проза, не функциональные директивы `eslint-disable*` / `@ts-expect-error` / `prettier-ignore` / `/// <reference` / `noqa` / `type: ignore`) — предупреждает. | WARN (exit 0) |
| `check-no-raw-env.py` | PostToolUse · `Edit\|Write` | Сканирует добавляемый код; если появился прямой доступ к переменным окружения (`process.env.*`, `os.environ`, `os.getenv`, `Deno.env.get`, …) вне явного config-модуля — предупреждает: крутилки/секреты через типизированный конфиг. | WARN (exit 0) |
| `approval-gate.py` | PreToolUse · `Edit\|Write` | Машинная точка одобрения замысла (§6): не даёт **создать** `plans/architecture/*.md` со `status: approved` (approved ставит владелец) и `plans/tz/*.md` без ссылки во frontmatter на существующую одобренную архитектуру. Правку уже существующих файлов не трогает. Исключения: `_template.md`, `*-orchestrator-prompt.md`. | BLOCK (exit 2) |
| `memory-link.py` | SessionStart | Делает каталог памяти харнеса (`~/.claude/projects/<путь>/memory`) симлинком на `<repo>/memory`, чтобы встроенная память писала прямо в репозиторий и переживала перенос папки. Лежавшие там записи переносит в репозиторий **без перезаписи** (коллизия имени → суффикс `-2`), строки индекса `MEMORY.md` дописывает без дублей. Идемпотентен. | BACKGROUND (exit 0) |
| `session-context.py` | SessionStart | Читает `.repobrain/graph.sqlite` и подаёт в контекст сессии число заметок второго мозга, помеченных протухшими, и до пяти заголовков. Ноль протухших, нет базы, любая ошибка — молчит. | HINT (exit 0) |
| `lesson-hint.py` | PreToolUse · `Bash` + PostToolUseFailure | Подаёт урок из `.claude/lessons/registry.jsonl` в момент действия: до выполнения команды и на её падении. Не более трёх подсказок за вызов, вывод до 4 000 символов, телеметрия в `.git/lesson-hints.jsonl` с ротацией по 1 МБ. Fail-open на любом входе, **никогда не возвращает `2`** — подсказывает, а не блокирует. | HINT (exit 0) |
| `repobrain-reindex.sh` | Stop (async) + git `post-commit` | Инкрементальный реиндекс RepoBrain после каждого хода агента И на любой коммит (включая ручной из терминала). Реиндекс сам переваривает `second-brain/` (ингест заметок в индекс) и метит протухшие заметки. Fail-open, в фоне, не блокирует. При первом запуске **сам ставит** git `post-commit` хук (идемпотентно). | BACKGROUND (exit 0) |

`settings.json` использует `$CLAUDE_PROJECT_DIR` — абсолютный путь к корню
проекта — так что хуки находятся независимо от текущей рабочей директории.

### Авто-реиндекс RepoBrain (`repobrain-reindex.sh`)

Мозг должен видеть свежий код — иначе капсулы устаревают. Реиндекс запускается
**двумя триггерами**, чтобы ничего не пропустить:

1. **Stop-хук** (async) — после каждого хода агента, ловит правки даже до коммита.
2. **git `post-commit`** — на любой коммит, включая ручной `git commit` из терминала.
   Хук ставится по действующему пути git-хуков (`core.hooksPath` / `.husky/` / `$GIT_DIR/hooks`).

Оба вызывают один скрипт. Он инкрементальный (`repobrain index`, ~секунды),
работает **в фоне** (`nohup`, detached) и **не блокирует** ни агента, ни `git commit`.
Наложения исключены локом (`$GIT_DIR/repobrain-reindex.lock`); лог —
`$GIT_DIR/repobrain-reindex.log`.

**Fail-open:** если нет `git`/`node` или RepoBrain ещё не собран
(`RepoBrain/apps/cli/dist/cli.js` отсутствует) — скрипт тихо выходит `0`.

**Самоустановка git-хука:** при первом запуске скрипт идемпотентно ставит
`post-commit` по **действующему** пути git-хуков (маркер `vibeos-repobrain-reindex`,
чужой хук не затирается — блок дописывается). Путь вычисляется, а не угадывается:
`core.hooksPath` (если задан), иначе `.husky/` при её наличии, иначе `$GIT_DIR/hooks`.
Поэтому в проекте с husky или с перенаправленными хуками реиндекс не отваливается
молча. Форсировать установку вручную: один раз запустить
`.claude/hooks/repobrain-reindex.sh`.

Что даёт реиндекс бесплатно (это команда `repobrain index`, не сам хук): ингест
заметок `second-brain/` в индекс (двойной поиск заметка↔️код) и аудит свежести —
пометка заметок, ссылающихся на исчезнувший код.

## Настройка

### `pre-bash-guard.py` — защищённые ветки

Вверху файла:

```python
PROTECTED_BRANCHES = ["main", "master"]
```

Добавь сюда `develop`, `release/*`-подобные имена и т.п.

### Энфорсмент-хуки: WARN → STRICT

`check-no-narrative-comments.py` и `check-no-raw-env.py` по умолчанию только
**предупреждают** (печатают в stderr, `exit 0` — правка проходит). Чтобы
**жёстко блокировать** такие правки, поставь вверху файла:

```python
STRICT = True
```

Тогда при находке хук вернёт `exit 2` и правка не применится. Начинай с WARN,
переходи на STRICT, когда команда привыкла к правилу и ложных срабатываний нет.

## Опционально: Grep/Glob-guard для индексного поиска кода

Если используешь индексный семантический поиск по коду (в ките это RepoBrain,
либо другой MCP-индекс), можно принуждать агента ходить в индекс вместо сырого
`Grep`/`Glob`. Это НЕ включено по умолчанию — включай, только если такой
индекс реально запущен, иначе заблокируешь себе поиск на пустом месте.

1. Положи рядом скрипт `grep-guard.sh`, который решает, пропускать ли вызов
   (например, exit 2 + подсказка «используй индексный поиск», когда демон жив;
   exit 0, когда индекс недоступен — fail-open).
2. Добавь блок в `settings.json` → `hooks.PreToolUse`:

```json
{
  "matcher": "Grep|Glob",
  "hooks": [
    {
      "type": "command",
      "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/grep-guard.sh",
      "timeout": 3000
    }
  ]
}
```

Держи guard **fail-open**: если индекс недоступен — пропускай `Grep`/`Glob`,
не блокируй работу.

## Ручная проверка хука

Хуки читают JSON из stdin. Проверить любой:

```bash
echo '{"tool_input":{"command":"git push origin main"}}' \
  | python3 .claude/hooks/pre-bash-guard.py; echo "exit=$?"

echo '{"tool_input":{"file_path":"src/a.ts","new_string":"// объясняющий комментарий тут"}}' \
  | python3 .claude/hooks/check-no-narrative-comments.py; echo "exit=$?"
```

После клонирования шаблона сделай хуки исполняемыми:

```bash
chmod +x .claude/hooks/*.py .claude/hooks/*.sh
```

# Технический фундамент (контур A, шаг A3)

Ты принимаешь подтверждённый product-brief и строишь фундамент, на котором скелет
задеплоится **сегодня же**. Владельца-новичка НЕ спрашиваешь ни о чём техническом —
все решения берёшь из скилла `decision-defaults` и доказываешь постфактум одним экраном.

## Порядок работы

### 1. Реши по дефолтам
Открой `decision-defaults` и возьми решения: стек, БД, auth, хостинг, структура папок,
стиль API. Для каждого реши: подходит ли дефолт под brief? Отступай от дефолта только
если brief этого требует (например, продукт — CLI-утилита, а не веб) — отступление
докажи и зафиксируй.

### 2. Проверь свежесть ДО генерации
Дефолтный стек эволюционирует быстрее твоих знаний. Перед скаффолдом:
- `context7` (context7) → актуальные версии и API ключевых пакетов;
- официальный скаффолдер стека (для дефолта — `create-next-app`, canary) вместо ручной
  сборки: он генерирует AGENTS.md/CLAUDE.md-механику и version-matched docs — это
  критично для качества генерации (58% → 96% на evals Vercel).

### 2а. Скаффолд в кит-проект (обязательный порядок — иначе скаффолдер откажет)

Кит уже лежит в корне (`CLAUDE.md`, `AGENTS.md`, `second-brain/`, `plans/`, `memory/`,
`RepoBrain/`), а официальные скаффолдеры отказываются работать в непустой папке:
`create-next-app` терпит только свой белый список (`.claude`, `.git`, `.gitignore`,
`docs`, `LICENSE`, `.vscode`, …) — файлы кита в него НЕ входят. Скаффолдить в корень
напрямую нельзя: получишь отказ «directory contains files that could conflict».

Порядок:
1. Скаффолди во ВРЕМЕННУЮ пустую папку вне проекта:
   `npx create-next-app@canary /tmp/<slug>-scaffold --yes`
2. Влей в корень проекта, не затирая кит:
   `rsync -a --ignore-existing /tmp/<slug>-scaffold/ ./`
   Исключения обязательны: `--exclude '.git' --exclude 'node_modules' --exclude '.next'`.
   Без них в проект уедут чужая история git и сотни мегабайт зависимостей.
3. Разбери оставшиеся коллизии ПОИМЕННО, показав владельцу, что сливаешь:
   `README.md` скаффолдера не нужен · `.gitignore` — слить строки, не заменять файл.
4. Убедись, что кит цел: `CLAUDE.md`, `.claude/`, `second-brain/`, `plans/` на месте.
5. **Исключи `RepoBrain/` из проверок проекта** — иначе `{{TYPECHECK_CMD}}` и `{{LINT_CMD}}`
   красные с первого дня на чужом коде: движок лежит в корне и попадает под `**/*.ts`.
   Для дефолтного стека: `tsconfig.json` → `"exclude": ["node_modules", "RepoBrain"]`;
   `eslint.config.mjs` → `globalIgnores([... "RepoBrain/**"])`; бегунок тестов →
   `exclude: [..., "RepoBrain/**"]`. RepoBrain собирается своим конфигом, он инструмент,
   а не код продукта.
6. `rm -rf /tmp/<slug>-scaffold` и `{{INSTALL_CMD}}` в корне.

Скаффолдер и кит спорят за `AGENTS.md`/`CLAUDE.md` — это ожидаемо, не баг: у кита
`AGENTS.md` симлинк на `CLAUDE.md`, а `next dev` дописывает в `AGENTS.md` свой блок
`nextjs-agent-rules` (и через симлинк он попадает в `CLAUDE.md`). Блок **оставь и
закоммить**: он велит агенту читать доки Next из `node_modules/next/dist/docs/` вместо
устаревшей памяти — это и есть version-matched docs. Next управляет им по маркерам сам.

Ручная сборка каркаса запрещена (см. анти-паттерны) — временная папка это не «руками»,
это обход отказа скаффолдера. Механика version-matched docs сохраняется полностью.

Отказал скаффолдер — перечитай его белый список в исходнике
(`vercel/next.js` → `packages/create-next-app/helpers/is-folder-empty.ts`), не гадай.

### 3. Структура папок — ДО первого файла кода
Разверни единый шаблон (подстрой имена под скаффолдер стека, не ломай его конвенции):

```
app/ или src/app/   ← фронт (страницы, компоненты)
api/ или src/app/api/ ← бэк (обработчики)
db/                 ← схема, миграции, сиды
docs/               ← операционка (деплой, флаги)
plans/              ← analysis / architecture / tz / archive
second-brain/       ← знание проекта
```

`plans/`, `second-brain/`, `memory/`, `CLAUDE.md` уже есть из кита — не пересоздавай и
**не дай скаффолдеру их затереть** (см. 2а).

### 4. Каркас + деплой
Собери walking skeleton из brief: каждый его пункт — маршрут/экран-заглушка со
сквозным проходом ключевого действия. Затем деплой по дефолту хостинга. Критерий
готовности шага — **владелец открывает URL и кликает свой продукт**.

Деньги/аккаунты: если для деплоя или БД нужен аккаунт — проведи владельца по
регистрации за руку (что нажать, что вставить), как в блюпринт-инструкциях: один шаг
за раз, жди подтверждения. Сам в чужие аккаунты не лезь, платное — только его решением.

### 5. Экран «что я выбрал и почему» (микро-урок, П1)
После деплоя — ОДИН экран владельцу, простым языком:

```
Твой проект стоит на:
• <Фреймворк> — почему (1 строка, человеческим языком)
• <БД> — почему
• <Auth> — почему
• <Хостинг> — почему, и что бесплатно
Папки: app/ — то, что видит пользователь; api/ — логика; db/ — данные.
Это выбор по проверенным дефолтам кита (см. decision-defaults). Захочешь иначе —
скажи, покажу сравнение и сделаем по-твоему.
```

Это информирование и обучение, НЕ запрос согласования.

### 6. Фиксация
- `second-brain/02_architecture/stack.md` — стек, версии, дата, ссылка на доказательство.
- Любое отступление от дефолта — там же: что · почему · кто решил.
- Чекпоинт-коммит (П7): «feat: walking skeleton задеплоен».

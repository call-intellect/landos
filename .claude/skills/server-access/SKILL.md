# Доступ к серверу

Владелец-новичок по умолчанию несёт пароль от root. Принять его — значит завести
секрет, который дальше надо всю жизнь прятать. Правильный ход — **сделать так,
чтобы секрета не существовало**.

## Железные правила

| Правило | Почему |
|---|---|
| **Пароль владельца не принимай.** Просят прислать — откажись и объясни. Пароль уже прозвучал в чате — скажи владельцу сменить его в панели хостера. | Присланный пароль навсегда в истории чата, в логах, в бэкапах. Отозвать нельзя. |
| **Вход только по SSH-ключу.** Пароль в `.env`/`.prod-access.local.json` + `sshpass` — запасной путь, а не дефолт. | Ключ = секрета в проекте нет вообще. Пароль в файле = plaintext на диске + `sshpass` светит его в `ps`. |
| **Пароль вводит владелец руками**, в свой интерактивный терминал (вкладка в IDE годится — агент её не видит). | Единственный момент, где пароль нужен, — установка ключа. Дальше он не нужен никогда. |
| **Приватный ключ живёт в `~/.ssh/`, не в репозитории.** Не копируй, не показывай, не коммить. | Вне репо → нечего добавлять в `.gitignore`, нечего забыть. |
| **Каждая команда на проде — с явным «да» владельца** под конкретную команду в текущей сессии. Общее «доступ есть» ≠ разрешение. | root даёт запись и выполнение, а не только чтение. См. [prod-ssh-access.md](../../../docs/operations/prod-ssh-access.md). |
| **По умолчанию read-only.** Write / restart / deploy — отдельное «да». | |

## Формат шага для новичка (обязателен)

Новичок не знает, что считать успехом, и несёт вывод обратно агенту. Это лишний
круг и потеря времени. Поэтому **каждый** шаг владельцу даётся тремя частями:

1. **Команда** — одной строкой, готовой к вставке, без плейсхолдеров.
2. **Что ты увидишь** — дословный признак успеха (`Number of key(s) added: 1`).
3. **Если не так** — типичный сбой и что делать.

Плюс предупреждай о неочевидном заранее: **при вводе пароля на экране не появляется
ничего** — ни точек, ни звёздочек. Новичок решает, что клавиатура сломалась.

## Процедура настройки с нуля

Шаги 1, 3, 5 делает агент. Шаг 2 — владелец (там пароль). Шаг 6 — решение владельца.

**1. Ключ (агент).** Имя — по проекту, чтобы не путать с чужими:
```
ssh-keygen -t ed25519 -f ~/.ssh/{{PROJECT_SLUG}}_prod -N "" -C "{{PROJECT_SLUG}}-prod $(whoami)@$(hostname)"
```
`ed25519` — современный дефолт (короче и надёжнее RSA). Пустая парольная фраза
(`-N ""`) — сознательно: агент ходит неинтерактивно, а защита ключа здесь — права
доступа файла и то, что он не покидает машину.

**2. Замок на сервер (владелец, в своём терминале).** Дай готовую строку:
```
ssh-copy-id -i ~/.ssh/{{PROJECT_SLUG}}_prod.pub {{SSH_ALIAS}}
```
- Увидишь: `Number of key(s) added: 1`.
- Первый раз спросит `Are you sure you want to continue connecting?` → `yes`.
- Спросит пароль → вводи вслепую, echo нет.
- `Permission denied` → пароль неверный, сбрось в панели хостера.

**3. Алиас (агент)** — в `~/.ssh/config`, вне репозитория:
```
Host {{SSH_ALIAS}}
    HostName {{PROD_HOST}}
    User {{PROD_USER}}
    IdentityFile ~/.ssh/{{PROJECT_SLUG}}_prod
    IdentitiesOnly yes
    StrictHostKeyChecking accept-new
```
`IdentitiesOnly yes` — иначе ssh перебирает все ключи подряд и ловит
`Too many authentication failures`.

**4. Проверка (агент) — обязательно с `BatchMode=yes`:**
```
ssh -o BatchMode=yes -o ConnectTimeout=10 {{SSH_ALIAS}} 'hostname; whoami'
```
`BatchMode=yes` **запрещает** спрашивать пароль. Ответ получен → доказано, что
пустил именно ключ. Без флага можно принять пароль за ключ и не заметить.

**5. Документация (агент)** — в `docs/operations/prod-ssh-access.md`: алиас, хост,
путь проекта, команды. **Секретов там нет** — их больше не существует.

**6. Закрыть пароль (решение владельца).** Ключ дверь не закрыл — он добавил
второй вход. Пока пароль включён, root перебирают боты круглосуточно:
```
ssh {{SSH_ALIAS}} "sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config && sshd -t && systemctl reload ssh"
```
`sshd -t` проверяет конфиг **до** перезагрузки, `reload` не рвёт текущую сессию.
Объясни страховку: консоль в панели хостера работает всегда и паролю подчиняется —
запереть себя насмерть нельзя. Владелец не готов сейчас → строка в
[реестр не-сделанного](../../../second-brain/04_not-done/README.md), вернуться позже.

## Что объяснить новичку (он не спросит сам)

- **Сервер** — чужой компьютер в дата-центре, включён всегда и виден из интернета.
  Твой ноутбук выключается и меняет сеть, сервер — нет. «Выкатить в прод» = положить
  приложение туда.
- **root** — полный хозяин машины, может всё, включая снести систему. Отсюда и ключи,
  и правило «каждая команда — с твоего да».
- **Ключ vs пароль** — публичный ключ (`.pub`) это **замок**, его не жалко, он едет на
  сервер. Приватный — **ключ**, лежит только у тебя. Пароль по сети не передаётся
  вообще, поэтому перехватывать нечего.
- **Где взять пароль** — в панели хостера, там же кнопка сброса root-пароля. После
  настройки ключа он не нужен в быту.

## Грабли

| Симптом | Причина | Что делать |
|---|---|---|
| `Permission denied (publickey)` после `ssh-copy-id` | Права на `~/.ssh` на сервере | `chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys` |
| `Too many authentication failures` | ssh перебирает все ключи | `IdentitiesOnly yes` в config |
| Команда висит и падает по таймауту | Пейджер под псевдо-tty (`git log`, `psql`, `systemctl`) | `GIT_PAGER=cat`, `--no-pager`, `-P pager=off` |
| Пайп-скрипт обрывается на середине | Вложенный вызов съел stdin | `</dev/null` на каждый вложенный вызов |
| root по SSH запрещён хостером | Норма для многих хостингов | Заходить обычным юзером, права повышать под конкретную команду |
| Мучение с кавычками в SQL/строках | Экранирование через несколько слоёв | Слать блок через base64: `echo <b64> \| base64 -d \| bash` |

## Когда ключ невозможен (запасной путь)

Хостер даёт только пароль и ключи не поддерживает — тогда и только тогда:
реквизиты в gitignored `/.prod-access.local.json`, доступ через `sshpass`.
Это **деградация**, а не альтернатива: пометь строкой в реестре не-сделанного с
причиной, чтобы вернуться, когда ключ станет возможен.

# Оценка источников и доказательность

## Формат строки claim-реестра
```
- [утверждение] → [источник: URL, дата снятия] → [тег]
```
Заполненный пример:
```
- Fathom даёт 1 шаблон резюме на free-tier → fathom.video/pricing, снято 2026-06-04 → verified
- Otter обрабатывает 100k+ команд → otter.ai/blog (пресс-релиз) → claimed (вендор о себе)
- Конкурент использует свой ASR на backend → вакансия HH «ASR-инженер» → inferred (профайлер слеп)
- Рынок AI-заметок ~N млрд → vc.ru + Коммерсантъ (разной природы) → triangulated(2)
```

## Теги (с мотивом)
- **verified** — первоисточник (репозиторий, релиз-ноут, доку, прямое наблюдение в demo) ИЛИ наш код через индексный поиск/`RepoBrain`.
- **triangulated(N)** — N источников **разной природы**. Не N перепечаток одного релиза: «volume ≠ validation». 10 СМИ с одного пресс-релиза = 1 источник.
- **claimed** — вендор о себе (мотив продать → понижай вес; funding-bias: свежепривлёкший раунд преувеличивает).
- **inferred** — профайлер фронтенда, вакансия, гипотеза, субъективная оценка (близость/угроза). Чтобы не приняли за измеренный факт.
- **unverified** — без источника → НЕ в синтез, только в «Ограничения».

## Триангуляция по типу факта (разная строгость)
| Тип факта | Минимум для вывода |
|---|---|
| Цифра рынка / цена | 2 независимых источника разной природы |
| Бенчмарк (латентность, точность, качество) | независимый замер; вендорский бенчмарк своего продукта = `claimed` |
| Поведение API/лимиты фичи | доку/changelog + мини-e2e, НЕ блог |
| Стек backend | вакансии + публичный код + доклад; иначе `inferred` |
Уровни уверенности: **High** = 3+ независимых разной природы; **Medium** = 2; **Low** = один / только маркетинг.

## CRAAP + SIFT (быстрый протокол)
- **CRAAP:** Currency (свежесть, дата), Relevance, Authority (кто автор, есть ли мотив), Accuracy (сверяемо?), Purpose (продать / информировать?).
- **SIFT:** **S**top → **I**nvestigate источник (кто и зачем) → **F**ind better coverage (латеральное чтение — что говорят ДРУГИЕ, не сам сайт) → **T**race to original (дойди до первоисточника цифры/бенчмарка).

## Пороги достоверности отзывов
- ≥50 отзывов за 12 мес → можно количественно (доля жалоб).
- <50 → 20–30 свежих качественно, с пометкой «слабый сигнал».
- Поля ценности: «What do you dislike», «почему ушли», «не хватает» → слабости конкурента → можем ли закрыть у себя.

## Технографика и её пределы (backend-слепота)
Wappalyzer / BuiltWith / WhatRuns / urlscan.io + HTTP-заголовки видят **только фронтенд / CDN / платёжки**. НЕ видны: серверный язык, БД, очереди, AI-pipeline, внешние провайдеры, реалтайм-инфраструктура. Для них — только вакансии + публичный код + инженерные доклады; всё прочее = `inferred`.

## Конфликт интересов и bias
- Вендор о себе → `claimed`, вес ↓. Аналитический отчёт, проданный вендором → bias.
- Funding-bias: после раунда — преувеличение traction.
- Конфликт источников НЕ усредняй — выноси блоком с гипотезой (миграция / устаревание / тёзка).

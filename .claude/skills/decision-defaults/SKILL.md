# Технические дефолты (справочник)

Формат строки: **Ситуация → Дефолт → Почему → Когда отступать.**
Владельцу-новичку эти решения НЕ выносятся как вопросы (П2); владельцу-середнячку,
который хочет иначе, — доказательство один раз, дальше его слово (П9).

## Стартовый стек (доказан ресёрчем 2026-07-14, 106 агентов, состязательная проверка)

| Слой | Дефолт | Почему (1 строка) |
|---|---|---|
| Фреймворк | **Next.js ≥16.2, App Router**, через `create-next-app` (canary) | самый используемый мета-фреймворк (20.8% SO-2025); ЕДИНСТВЕННЫЙ с version-matched docs для агентов: AGENTS.md/CLAUDE.md из коробки, качество генерации 58%→96% (evals Vercel) |
| Язык | **TypeScript** | «TS победил»: 40% пишут только на нём; один язык на фронт и бэк |
| БД | **PostgreSQL via Supabase** | Postgres — БД №1 (55.6%); Supabase-паттерн проверен Lovable на новичках: auth-таблицы + RLS из простого запроса |
| Auth | **Supabase Auth** | готовое, а не самописное; свою криптографию не пишем никогда |
| ORM | **на старте НЕ ставим** — Supabase-клиент | Prisma не доказан ресёрчем; AI-платформы обходят ORM; ORM — отдельное решение при росте |
| UI | **Tailwind + shadcn/ui** | консенсусный AI-дефолт всех билдеров (Lovable/v0/Bolt) |
| Хостинг | **Vercel (hobby)** | деплой одной командой, автодетект Next.js, бесплатный тир для скелета |

Обязательное условие стека: механика version-matched docs включена (AGENTS.md +
доки в node_modules) — без неё качество генерации проваливается. Ловушка для правил:
server/client components — держать правило в стек-паке nextjs-react.

## Архитектура и сложность (П4)

| Ситуация | Дефолт | Когда отступать |
|---|---|---|
| Архитектура приложения | Монолит | микросервисы — только при ДОКАЗАННОЙ необходимости (независимый скейлинг, команды); «на вырост» — запрещено |
| Кэш/очереди/фоновые воркеры | Не ставить, пока не больно | измеренная проблема производительности или реальный фон (письма, долгие задачи) |
| API-стиль | REST (route handlers) | GraphQL/gRPC — по доказанной необходимости, не по моде |
| Реалтайм | Supabase Realtime | отдельный WS-сервер — только при доказанной нехватке |

## Либа vs свой код (П3)

Дефолт: **живая библиотека вместо своего кода.** Критерии «живой»: регулярные релизы
за последние месяцы, широкое использование, открытые issues разгребаются. Порядок
воронки: [1] есть ли уже у нас в проекте (индекс кода) → [2] есть ли живая либа
(context7 + web) → [3] только теперь пиши сам. 10 своих строк вместо 1 строки
либы — дефект ревью.

## Типовые потребности MVP

| Потребность | Дефолт |
|---|---|
| Файлы/картинки | Supabase Storage |
| Почта | Resend (бесплатный тир) |
| Платежи | Stripe — ТОЛЬКО решением владельца (деньги, граница П2) |
| Аналитика | Vercel Analytics / Plausible — простое, без сборки своей |
| Логи/ошибки | console + Vercel logs на старте; Sentry — при первом реальном инциденте |

## Тесты (П5)

| Что | Покрывать? |
|---|---|
| Бизнес-логика, деньги, доступ/права | ОБЯЗАТЕЛЬНО, в той же фазе |

| Регрессии после инцидентов | обязательно (debug-recovery) |

## Структура папок

`db/` схема+миграции · `docs/` операционка · `plans/` планирование · `second-brain/` знание.
Создаётся в шаге A3 ДО первого кода (project-bootstrap).

## Правила отступления (П9)

1. Владелец предложил иное → одно доказательное возражение (варианты, почему дефолт
   лучше) → решение владельца финально, без переспрашивания.
2. Агент видит, что дефолт не подходит под задачу → отступай сам, но докажи в
   один абзац и зафиксируй.
3. Любое отступление — строка в `second-brain/02_architecture/stack.md`:
   дата · что · почему · кто решил.

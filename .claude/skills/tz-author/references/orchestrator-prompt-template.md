# Шаблон парного orchestrator-prompt

Нужен только для крупных/многофазных ТЗ. Для мелких — оркестратор берёт ТЗ напрямую, промпт не создавай. Файл: `plans/tz/YYYY-MM-DD-<имя>-orchestrator-prompt.md`.

**Главное правило: НЕ дублируй тело ТЗ — ссылайся.** Дубль = риск рассинхрона: правка в ТЗ не доедет до промпта. Промпт — это «как запустить оркестратор по этому ТЗ», а не копия ТЗ.

**Форма свободная.** Обычный markdown без COPY-маркеров и без frontmatter достаточно. Маркеры `↓↓↓ COPY FROM HERE ↓↓↓` и хвост «Заметки для владельца (НЕ копировать)» — опция, не обязанность.

## Скелет

```markdown
# Запуск tz-orchestrator: <feature>

Реализуй ТЗ `plans/tz/YYYY-MM-DD-<имя>.md` как оркестратор-разработчик (скилл tz-orchestrator).
Код руками не пишешь — ведёшь фазы силами суб-агентов, каждую приёмку проходишь сам.

## Порядок чтения (один раз)
1. `CLAUDE.md` (+ `.claude/CLAUDE.md`).
2. `second-brain/index.md` → профильная заметка `<feature>`, нужные архитектурные заметки.
3. ПОЛНЫЙ текст ТЗ + связанные ТЗ/анализ из `relates_to`.
4. Подключи скиллы проекта: core-engineering-standards, стековые/доменные конвенции,
   дисциплина миграций и безопасных seeds, strict-production-review-gate,
   скилл навигации по архитектуре.

## Инструменты
- Индекс кода (RepoBrain; в ките это RepoBrain) первым, не слепой grep/glob — при живом
  демоне хук может блокировать Grep/Glob. Fallback при недоступном индексе: ripgrep + Read.
- context7 (резолв id библиотеки → запрос к её докам) для внешних либ; не угадывать API.
- path:line в ТЗ могли устареть — верифицируй по якорю-символу перед правкой.

## Граф фаз (контракт порядка)
Фаза 0 → 1 → 2 … строго последовательно, без перепрыгиваний.
Параллельны: <если есть — какие и почему независимы>.
«A раньше B», потому что <зависимость>.

## Определение «фаза закрыта»
- Acceptance фазы пройдены ТОБОЙ (греп-маркеры, тесты, команды) — не по отчёту агента.
- `{{TYPECHECK_CMD}}` (вкл. тесты) + `{{LINT_CMD}}` (0) + `{{BUILD_CMD}}` зелёные; `{{TEST_CMD}}` по модулю.
- strict-production-review-gate по git diff — отдельно от тестов.
- Коммит явными путями (не git add .); фаза [x] в ТЗ; следующая фаза в том же ответе.

## Факт-чек (не верь отчёту суб-агента)
Суб-агенты иногда отмечают [x] без реальных Edit. После каждого: git status +
греп ключевых маркеров (символы/эндпоинты/enum) в файлах. В промпт кодеру —
«re-Read после каждого Edit + git status в отчёт».

## Failure-modes
- Красное/недоказано → уточни промпт, верни агенту; долги не тащи.
- Параллельная сессия (git fetch + log) — усиливай, не дублируй/переписывай.
- Push — только по явному подтверждению владельца.
```

## Чек перед сдачей промпта
- [ ] Ни одна секция не копирует тело ТЗ дословно — только ссылки.
- [ ] Граф фаз согласован с фазами ТЗ.
- [ ] Указаны индекс кода + fallback и context7.
- [ ] Есть определение «фаза закрыта» и факт-чек.

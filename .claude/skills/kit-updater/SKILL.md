# Обновлялка кита

Обновляет уже установленный кит до новой версии. **Жёсткая гарантия: работа пользователя не теряется никогда.** Файлы кита, которые пользователь не трогал, обновляются; которые трогал — аккуратно сливаются; при конфликте остаётся версия пользователя. Его проект, знания и планы не трогаются вообще.

**Принцип — супер-просто:** единственное действие пользователя — «да». Никаких выборов, ручных слияний и технических вопросов. Всё делает агент.

## Когда

- Владелец: «обнови кит» / «есть обновление?» / «вышла новая версия».
- Проактивная проверка при старте (хук `check-kit-update`) вбросила «доступна новая версия» → предложи обновиться и, при «да», иди по шагам ниже.

## Шаги

### Шаг 1. Ключ (один раз)
Движку нужен лицензионный ключ, чтобы скачать версии с сервера (обновление **бесплатное** — лимит активаций не тратится).

- Есть файл `.vibeos/license-key` в корне проекта → ничего не спрашивай, переходи к шагу 2.
- Нет → спроси владельца **в чате** простым языком: «Вставь свой ключ VibeOS — сохраню локально, больше спрашивать не буду». Получил → запиши в `.vibeos/license-key` и убедись, что `.vibeos/` в `.gitignore` (движок сам ставит `.vibeos/.gitignore` с `*`, но проверь). **Ключ — секрет: в git он попасть не должен.**
- Ключ вводи через файл, **не** полагайся на интерактивный ввод движка (агент запускает его не-интерактивно — stdin-запрос зависнет).

### Шаг 2. Запуск движка
Из корня проекта:
```bash
node .claude/updater/update.mjs
```
Движок сам: определит установленную версию, сверит с сервером, сделает **точку отката**, скачает нужные версии (со сверкой контрольной суммы), сольёт по трём полкам и напечатает JSON-итог в stdout (человеческий прогресс — в stderr).

Формат итога (stdout):
```json
{"from":"0.6.0","to":"0.7.0","replaced":[...],"merged":[...],"kept_yours":[...],"added":[...],"deleted":[...],"checkpoint":"git"}
```
`up_to_date` в поле `status` → уже последняя, сообщи «у тебя уже последняя версия» и всё.

### Шаг 3. Отчёт простым языком (при успехе, exit 0)
Переведи JSON в человеческий отчёт (не показывай JSON). Образец:

> ✅ Обновил кит **0.6.0 → 0.7.0**.
> • Обновил файлы кита — N шт.
> • Твою работу не трогал (проект, знания, планы).
> • Точку отката сделал — если что, вернём одним шагом.

Если `kept_yours` не пуст — добавь **одной строкой, без требования что-то делать**:
> Один-два файла ты менял под себя, и они изменились в новой версии — **оставил твою версию**. Захочешь глянуть, что там нового, — скажи «покажи», по желанию.

Если `skipped` не пуст (редко: файл не удалось обработать, напр. конфликт типа файл/папка) — сообщи спокойно: «пару файлов не смог обновить, оставил как есть; твоя работа цела».

Не заставляй выбирать. Не вываливай списки путей, если их много, — скажи числом.

### Шаг 4. Если движок упал (exit ≠ 0) — не паникуй
Обновление устроено безопасно: **точка отката сделана ДО изменений**, и ни один файл пользователя не теряется даже при обрыве. Сообщи спокойно:

> Обновление прервалось на полпути (причина: <кратко из stderr>). **Твоя работа в сохранности** — я сделал точку отката до начала. Откатить назад к ней?

При «да» — откат: если чекпоинт был `git` → `git reset --hard` на коммит `checkpoint before kit update…` (или `git reset --hard HEAD~1`, если чекпоинт-коммит последний); если `backup:<путь>` → верни дерево из этой папки. Затем предложи попробовать позже.

Две неудачные попытки подряд — не чини на ходу, включай скилл `debug-recovery`.

## Границы
- Только вперёд (обновление), не откат версии.
- Пользователь не выбирает и не сливает руками — при конфликте его версия остаётся, мы просто сообщаем.
- Файлы пользователя (`theirs_never_touch`: second-brain 01–05/13, plans, docs, memory, его код) не трогаем.

## Проверка движка (для разработки кита)
Тесты запускать glob-формой (директорная форма `node --test <dir>/` на Node 24 не работает):
```bash
node --test .claude/updater/__tests__/*.test.mjs
```

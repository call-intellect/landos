## Критерии приёмки (EARS + Given/When/Then)

<!-- КАЖДЫЙ критерий имеет стабильный ID R1..Rn. Формулируй по шаблону EARS, затем дай
     проверяемый сценарий Given/When/Then. Каждая ФАЗА реализации ниже помечает, какие R

**Нотация EARS (Easy Approach to Requirements Syntax) — выбери подходящий шаблон на требование:**
- **Ubiquitous** (всегда): «Система ДОЛЖНА <реакция>.»
- **Event-driven** (по событию): «КОГДА <триггер>, система ДОЛЖНА <реакция>.»
- **State-driven** (в состоянии): «ПОКА <состояние>, система ДОЛЖНА <реакция>.»
- **Optional** (при наличии функции): «ГДЕ <фича включена>, система ДОЛЖНА <реакция>.»
- **Unwanted** (обработка ошибки): «ЕСЛИ <нежелательное условие>, ТО система ДОЛЖНА <реакция>.»

| ID | Требование (EARS) | Приёмочный сценарий (Given / When / Then) |
|---|---|---|
| **R1** | КОГДА _<триггер>_, система ДОЛЖНА _<реакция>_. | **Given** _<исходное состояние>_ **When** _<действие>_ **Then** _<наблюдаемый результат>_ |
| **R2** | Система ДОЛЖНА _<инвариант>_. | **Given** … **When** … **Then** … |
| **R3** | ЕСЛИ _<ошибка/край>_, ТО система ДОЛЖНА _<безопасная реакция>_. | **Given** … **When** … **Then** … |

_Добавляй строки R4..Rn по необходимости. Каждый критерий должен быть наблюдаемым (можно проверить руками или тестом), а не «работает хорошо»._

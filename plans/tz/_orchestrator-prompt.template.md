# Стартовый промпт исполнителю: НАЗВАНИЕ_ФИЧИ

## Что реализуем

- **ТЗ (контракт):** `plans/tz/YYYY-MM-DD-НАЗВАНИЕ_ФИЧИ_SLUG.md` — источник правды по scope, фазам и критериям приёмки R1..Rn.
- **Архитектура (замысел, approved):** `plans/architecture/YYYY-MM-DD-НАЗВАНИЕ_ФИЧИ_SLUG.md` — читай, если непонятно «зачем так».

Сначала прочитай оба файла целиком. Если архитектура не `approved` — СТОП, реализация запрещена, вернись к владельцу.

## Порядок работы

1. **Картография.** Пойми затронутый код через `RepoBrain` (или проектный инструмент осмотра). Собери список файлов, которые фаза тронет, ДО правок.
2. **Фаза за фазой строго по списку из ТЗ.** Не перескакивай, не делай несколько фаз «оптом». Одна фаза → правки → приёмка → коммит → следующая.
3. **Точечные изменения.** Минимальный безопасный диф под текущую фазу. Не рефактори мимо scope.
4. Если по ходу вскрылась развилка, меняющая замысел — фиксируй в `plans/decisions-log.md` и продолжай; если это «решение владельца» (необратимое) — остановись и спроси.

## Приёмка КАЖДОЙ фазы (обязательный ритуал)

> Не верь отчёту суб-агента «сделано». Проверяй сам, руками, по шагам. Отчёт исполнителя — гипотеза, а не факт.

1. **`git status` / `git diff`** — что реально изменилось на диске. Совпадает ли с заявленным.
2. **Поиск маркеров-заглушек** — прогони `RepoBrain` по диффу на `TODO`, `FIXME`, `throw new Error("not implemented")`, закомментированный код, пустые заглушки.
3. **Re-Read ключевых мест.** Перечитай изменённые участки своими глазами (особенно если поиск по коду мог быть урезан хуком/индексатором) — убедись, что логика на месте, а не только сигнатуры.
4. **Сборка:** `{{TYPECHECK_CMD}}` → `{{LINT_CMD}}` → `{{BUILD_CMD}}` — все зелёные.
5. **Тесты:** `{{TEST_CMD}}` — проходят; при необходимости добавлены тесты под критерии этой фазы.
6. **Критерии приёмки построчно.** Возьми R-критерии, которые фаза «Закрывает», и пройди каждый Given/When/Then вручную/тестом. Отметь R как выполненный только увидев наблюдаемый результат.

Не прошло хоть что-то — фаза НЕ принята, возвращаем на доработку. Зелёная сборка при неверном поведении — тоже провал.

## Коммит по фазам

- Коммить **только явными путями** (`git add <путь> <путь>` — перечисляй файлы), никогда `git add .` / `-A`.
- Коммит — после принятой фазы: `тип(область): описание` (Conventional Commits).
- В теле коммита отметь, какие R закрыты (`Закрывает: R3, R7`).
- Push — только с явного подтверждения владельца (разрешение на коммит ≠ разрешение на push).
- После коммита отметь фазу `[x]` в ТЗ.

## Завершение

- Заполни блок «Итог» в ТЗ: реализовано целиком или нет, какие R закрыты, что осталось.
- Обнови связанную документацию проекта, если менялась бизнес-логика/архитектура.

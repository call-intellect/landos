# Слой памяти агента

Персональная память AI-агента между сессиями: короткие атомарные заметки, которые агент подхватывает в начале работы, чтобы не переоткрывать одни и те же факты, грабли и предпочтения.

## ВАЖНО: где живёт реальная память

Источник правды — **этот каталог в репозитории**: `<repo>/memory/`. Именно здесь лежат `MEMORY.md` и файлы фактов, и именно поэтому память переживает перенос папки, клон и смену машины.

Каталог харнеса `~/.claude/projects/<project>/memory/` — **симлинк** на него. Симлинк ставится сам, хуком `.claude/hooks/memory-link.py` при старте сессии; если по этому пути был настоящий каталог с записями, хук переносит их в репозиторий без перезаписи.

```
~/.claude/projects/<project>/memory  →  <repo>/memory
```

Писатель остаётся один — встроенная память агента; кит только меняет ей адрес. Спорить двум слоям не о чем.

**Выносить память из репозитория наружу запрещено.** Имя каталога харнеса кодирует абсолютный путь проекта (`/` → `-`), поэтому память, живущая только там, исчезает при первом же переезде.

Проверка, что канал жив: строка `каталог памяти агента ведёт в репозиторий` в табеле стенда (прибор `memory`, `memory_link_ok`). Красная строка означает, что автоподача не работает; сами записи при этом на месте и продолжают находиться выжимкой — они индексируются как `agent_memory`.

## Четыре типа заметок

Тип задаётся префиксом имени файла и полем `metadata.type`.

| Тип | Что кладём | Когда заводить |
|---|---|---|
| `user` | Устойчивые предпочтения и контекст пользователя/владельца (как общаться, что важно, стиль решений) | Пользователь высказал предпочтение, которое переживёт эту задачу |
| `feedback` | Поведенческое правило для агента: как поступать в повторяющейся ситуации, чего не делать | Получил корректирующий фидбек; ошибся способом, который повторится |
| `project` | Технический факт о проекте: контракт, ловушка тулинга, поведение сборки/окружения | Вскрыл неочевидную деталь проекта ценой времени |
| `reference` | Указатель на ресурс: где что лежит, доступы (без секретов), справочные координаты | Нашёл ресурс/доступ, к которому будешь возвращаться |

Пограничные случаи: правило про **конкретный модуль** — это `project`; общий стиль работы агента — `feedback`; предпочтение конкретного человека — `user`.

## Имя файла

```
<type>_<slug>.md
```

`slug` — краткий kebab-case (напр. `feedback_verify-before-delete.md`, `project_toolchain-setup.md`). Один факт = один файл.

## Frontmatter (обязателен)

```yaml
---
name: <slug-без-типа>
description: "Одно предложение: что помнить и что из этого следует."
metadata:
  node_type: memory
  type: user | feedback | project | reference
  originSessionId: <id-сессии-где-факт-родился>
---
```

- `node_type` всегда `memory`.
- `type` — один из четырёх выше.
- `originSessionId` — id сессии-источника (для аудита; если неизвестен — оставь плейсхолдер).

## Тело заметки

Короткое и плотное. Обязательные смысловые части:

- **Why:** почему этот факт истинен / какой случай его породил (конкретика: файл, команда, симптом, цена ошибки).
- **How to apply:** что конкретно делать в следующий раз — операциональная инструкция, а не абстракция.
- `[[wiki-links]]` на связанные заметки (по `name` без расширения) — память связная, ссылки не пропускай.

Держи одну мысль на файл. Разрослось на две темы — раздели на два файла.

## Строка в индексе `MEMORY.md`

Каждый файл — одна строка в `MEMORY.md`:

```
- [Заголовок](<type>_<slug>.md) — плотное резюме факта в 1 предложение.
```

Резюме — не пересказ, а самое ценное сжатие: что помнить + следствие/действие. Порядок строк — по важности.

## Связь с дистилляцией рефлексий

Память пополняется не «на каждый чих», а через дистилляцию: периодически проходишь по накопленным рефлексиям сессий и выносишь в память только повторяющееся или дорогое.

Критерий переноса (хотя бы один):
- урок повторился в ≥2 рефлексиях; или
- грабля с ценой >1 часа потерянного времени; или
- факт меняет способ работы (новая команда, новый подход, новый доступ).

После переноса помечай обработанную рефлексию как «distilled», чтобы не разбирать повторно. Разовые детали конкретной задачи в память не идут — они остаются в рефлексии.

## Безопасность

- **Файлы памяти едут в git.** Записанное здесь видно всем, у кого есть репозиторий, — поэтому граница проходит по классу факта, а не по «выглядит технически».
- **Секретов нет никогда:** пароли, ключи, токены, строки подключения с паролем, приватные ключи. Заметка `reference` хранит только указатель «где лежит» (напр. имя gitignored-файла) и правило обращения. Запрет машинный: хук `env-guard` проверяет каждую запись в `memory/**.md` по списку сигнатур и блокирует её, назвав сработавшую, — правило «секретов нет никогда» больше не держится на внимании агента.
- **Координаты инфраструктуры записывать можно и нужно:** адрес прод-сервера, имя хоста, домен, порт — это конфигурация, а не секрет, и она уже живёт в документации операций. Память, которая не помнит, какой сервер прод, не выполняет своего обещания: владелец платит за то, чтобы каждая сессия переспрашивала. Запрет на такую запись защищал бы только от того, что и так лежит в репозитории.
- Реальные креды — в gitignored-файле окружения, читаются в момент использования, в чат не печатаются.

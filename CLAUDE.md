# {{PROJECT_NAME}} — рабочие правила проекта

**Источник правды — код и `second-brain/`.** Навигация — `second-brain/index.md`, процесс — `second-brain/00_system/TASK_WORKFLOW.md`.

## 1. Общение (жёсткое правило)
- **Всё владельцу — по-русски**, любой ответ; другой язык — по его просьбе.
- Варианты — текстом, с плюсами и минусами; **рекомендованный первым, «(рекомендую)»**.
- **«Рекомендую» без доказательства — брак:** проверяемый факт + **контр-проверка** («что увидели бы, будь вывод неверен») + цена ошибки. Нечем доказать — так и скажи.
- **Техвопросы владельцу НЕ задаются** — решай по `decision-defaults` и докажи постфактум; варианты вместо решения — то же нарушение. Исключение: **деньги, аккаунты, необратимое удаление — решение владельца.**
- **Советник, не блокиратор:** возражение одно и ДО исполнения, дальше как сказал владелец; отступление от дефолта — в `second-brain/02_architecture/stack.md`.

## 2. Без нарративных комментариев в коде
Код самодокументируем. Объясняющие комментарии не пиши, встреченные удаляй. Разрешены ТОЛЬКО функциональные директивы (`eslint-disable*`, `@ts-expect-error`). _(Хук `check-no-narrative-comments`.)_

## 3. Ship-On — выкатываем включённым
Фича идёт в прод включённой; «включим потом» запрещено. Законных флага два: kill-switch и решение владельца. Флаг — строка в `docs/operations/feature-flags.md`.

## 4. Конфиг: секреты в ENV, крутилки — в рантайм-настройки
В ENV — ТОЛЬКО секреты и строки подключения. Пороги, лимиты, флаги, TTL, веса — динамический конфиг `admin → env → code-fallback`. Доступ к env мимо схемы запрещён. _(Хук `check-no-raw-env`.)_

## 5. Знание vs планы
Факт → `second-brain/`; замысел → `plans/`. Что куда — `second-brain/00_system/STRUCTURE_RULES.md`.

## 6. Два контура работы + жёсткий gate
**A — «первый скелет»**: `idea-interviewer` → `project-bootstrap`, скелет в первый день.
**B — «каждая следующая фича»**: `feature-analyst → solution-blueprint → tz-author → tz-orchestrator → qa-user-tester → strict-production-review-gate`.
**Gate:** ТЗ не пишется, пока нет `plans/architecture/<feature>.md` со `status: approved`. Владелец ставит `approved`, агент — никогда сам.
**Глазами пользователя:** «готово» по фиче с UI — только после прохода `qa-user-tester` через браузер, не по коду и не по тестам.
**Лёгкая тропа:** 1–2 файла без развилок — прямой маршрут, критерий в `core-engineering-standards`.

## 7. Реестр не-сделанного
Отложил / вскрыл пробел / заблокирован → сразу строка в `second-brain/04_not-done/README.md`: четыре поля (дата · что · **почему**, включая «кто разблокирует» · ссылка на детали), ≤400 символов.

## 8. Завершение работы по триггеру
Триггеры: `git push` · «всё/спасибо/ок» · >10 рефлексий. Сработал — делаешь ПЕРВЫМ, до ответа владельцу. **Рефлексию и знание пишет агент сам; предложить «написать рефлексию?» вместо того, чтобы её написать, — нарушение.** Шаги — post-push-хук и `second-brain/00_system/UPDATE_AFTER_CODE_CHANGE.md`: знание, рефлексия, `CHANGELOG.md` кита, деплой-лог, дистилляция.
Плюс «запомнить решение»: развилка по типу там же, `memory/*.md` коммить с работой.

## 9. Git
- Коммить ТОЛЬКО своё; никогда `git add .`/`-A` — пути явно. Untracked не трогать.
- **Чекпоинт-коммиты:** каждая зелёная фаза = коммит.
- `git push` — только с явным подтверждением на КАЖДЫЙ push; рефлексия пушится сразу после основного.
- Формат: `тип(область): описание`.

## 9а. Стоп-кран отладки (жёсткое правило)
Две неудачные попытки исправить одну проблему → быстрые фиксы ЗАПРЕЩЕНЫ, переключайся в `debug-recovery`. Развалено заплатками — откат к зелёному чекпоинту.

## 11а. Суб-агенты (жёсткое правило)

# VibeOS — установка (инструкция для ИИ-ассистента)

**Что это.** Один файл-инструкция из архива VibeOS. Открой его в Claude Code (VS Code или
терминал) и скажи: **«Установи мне это»**. Ассистент сам развернёт VibeOS в твоём
проекте — новом или уже существующем.

**Результат:** твой Claude Code работает по рельсам VibeOS — распаковывает идею
простыми вопросами, сам принимает технические решения (и доказывает их), строит
задеплоенный скелет продукта в первый же день, а дальше ведёт каждую фичу по
конвейеру качества с защитой от «заплатки на заплатку».

---

## 🤖 Инструкция для ИИ-ассистента

Пользователь может быть **не программистом**. Правила:

1. **Один шаг за раз.** Сделал → сообщил результат простым языком → дальше.
2. **Никаких технических вопросов пользователю.** Все техрешения — по правилам кита.
   Спрашивать можно только: про его продукт/идею, про деньги/аккаунты, и куда ставить
   (новый проект или существующий), если непонятно из контекста.
3. **Ничего не затирать без спроса** — особенно в существующем проекте.
4. **Критерий готовности — раздел «Тест» в конце.** Пока не прошёл — не готово.

### Шаг 1. Определи режим

- Папка проекта пустая или содержит только README → **режим «Новый проект» (A)**.
- В папке есть код → **режим «Живой проект» (B)**.

### Шаг 2. Распакуй архив

```bash
mkdir -p /tmp/vibeos-kit
tar -xzf vibeos-kit-<version>.tar.gz -C /tmp/vibeos-kit
```

Внутри — весь кит вместе с **RepoBrain** (мозг репозитория, индекс кода) в папке
`RepoBrain/`. Без него кит работает как «дисциплина без памяти» — RepoBrain обязателен.

В корне распакованного архива лежит `kit.manifest.yaml` — паспорт версии кита. Он едет
**в проект** (шаг 3A/3B ниже), а не остаётся в `/tmp`: `/tmp` чистится системой, а по
этому файлу будущее обновление узнаёт, какая версия у тебя стоит.

### Шаг 3A. Новый проект

1. Скопируй в корень проекта из распакованного архива (`/tmp/vibeos-kit/`):
   `CLAUDE.md`, `AGENTS.md`, `.claude/`, `second-brain/`, `plans/`, `docs/operations/`, `memory/`,
   `.gitignore`, `.repobrainignore`, `kit.manifest.yaml`.
   Копируй `docs/operations/`, а не весь `docs/`: остальное в `docs/` (напр. `TEMPLATE-DESIGN.md`) —
   про устройство самого кита, проекту клиента оно не нужно.
   `.gitignore` копируй **первым**: он глушит `.env` и `.env.*`. Без него первый же
   `git add` может увезти секреты в историю — `env-guard` запрещает **читать** `.env`,
   но коммит не останавливает. Копируй `cp -R` (не `zip`) — `AGENTS.md` должен остаться
   симлинком на `CLAUDE.md`.
2. Заполни плейсхолдеры `{{...}}` (список в README.md): `{{PROJECT_LANGUAGE}}` →
   `русский` по умолчанию, без вопроса (общение по-русски уже зашито в CLAUDE.md §1;
   спрашивай другой язык только если клиент сам об этом просит), остальное —
   значениями по умолчанию из скилла `decision-defaults` (стек заполнишь на шаге
   project-bootstrap, когда он определится).
3. **Подними мозг RepoBrain** (шаг 3В ниже) — обязательно.
4. Скажи пользователю перезапустить Claude Code (или открыть `/hooks`), чтобы
   подхватились настройки.
5. → Тест, затем передай слово скиллу `idea-interviewer`: «Расскажи, что хочешь
   построить?»

### Шаг 3B. Живой проект (brownfield)

**Бережно. Ничего не удалять и не перезаписывать без показа и согласия.**

1. **Инвентаризация.** Осмотри проект: стек, структура, есть ли CLAUDE.md / .claude/ /
   правила других инструментов. Покажи пользователю картину: «вот что у тебя уже есть».
2. **Слияние правил.** Существующий CLAUDE.md НЕ затирай: покажи по шагам, что
   предлагаешь добавить/изменить из кита и почему это лучше («вот так лучше, потому
   что…»). Согласился — вноси. Конфликт — его слово финально.
3. **Настройки и хуки.** Слей `.claude/settings.json` кита с существующим (существующие
   правила сохраняются); скопируй хуки. `.gitignore` — **слей строки, не заменяй файл**
   (у проекта свой); убедись, что `.env` и `.env.*` заглушены. `.repobrainignore` скопируй;
   у проекта свой — **слей строки, не заменяй файл**. `kit.manifest.yaml`
   скопируй — по нему обновление узнает версию.
4. **Второй мозг из кода.** Скопируй из распакованного архива `second-brain/`, `plans/`,
   `docs/operations/` (пустые каркасы; `docs/TEMPLATE-DESIGN.md` — про кит, не копируй) и
   запусти `second-brain/00_system/BOOTSTRAP_FROM_CODE.md` — второй мозг
   заполняется ИЗ реального кода.
5. **Подними мозг RepoBrain** (шаг 3В ниже) — обязательно, он и проиндексирует код.
6. Перезапуск Claude Code → Тест.

### Шаг 3В. Мозг RepoBrain (обязателен для обоих режимов)

RepoBrain лежит в `RepoBrain/` внутри распакованного архива. Он индексирует код проекта и отдаёт
агенту компактную капсулу контекста вместо чтения всего репо — это движок рефлекса
«не изобретай» и экономии токенов.

Скопируй `RepoBrain/` в корень проекта и подними одной командой (нужен Node 18+):

```bash
cd RepoBrain
./install.sh ..        # сборка + команда `repobrain` + setup в корне проекта
```

Аргумент `..` — это корень проекта, куда ставится кит. Запускай из скопированной папки,
а не из `/tmp/vibeos-kit/`, иначе RepoBrain проиндексирует распакованный архив.

`install.sh` собирает мозг, выставляет команду `repobrain` и запускает `setup` в корне
проекта: регистрирует MCP-сервер в `.mcp.json` (Claude Code) и `.cursor/mcp.json` (если
есть Cursor) — **уже подключённые MCP-серверы сохраняются**, наш добавляется рядом;
пишет `.repobrain.yaml`; индексирует код; собирает вики кода (ниже). Ручной `claude mcp add`
больше не нужен. Команда идемпотентна — повторный запуск ничего не ломает.

Наш `AGENTS.md` (симлинк на `CLAUDE.md`) `setup` не трогает — симлинк он не перезаписывает
даже с `--force`. Правило «RepoBrain первым» и так лежит в `.claude/CLAUDE.md`.

Проблемы сборки/окружения (нет Node и т.п.) — запасной путь `docker compose up`
в папке `RepoBrain/`.

**Вики кода** — `setup` собирает видимую папку `wiki/` в корне: авто-справочник из кода
(страницы модулей с ключевыми функциями, графом зависимостей и цитатами из
`second-brain/`). Дальше её освежает каждый `index`; генерация детерминирована, так что
лишних diff-ов в git не будет. Чужую рукописную `wiki/` RepoBrain не перезапишет —
только свою, помеченную маркером `.repobrain-wiki`.

Три части знания кита (разные имена — не пересекаются): `wiki/` — авто-справочник кода
«что есть»; `second-brain/` — второй мозг, «почему мы сделали так» (пишем мы); `TOUR.md`
в корне — путеводитель по самому киту.

Эмбеддинги по умолчанию **выключены** (graph-first, D18) — индекс быстрый и полностью
офлайновый, ничего не качается. Включаются опционально в `.repobrain.yaml`
(`embedding.enabled: true`) — тогда при первой индексации один раз скачается модель.

**Авто-реиндекс включается сам.** После сборки RepoBrain индекс держится свежим без
ручных команд: хук `.claude/hooks/repobrain-reindex.sh` реиндексирует инкрементально
после каждого хода агента (Stop-хук) и на любой коммит — он при первом запуске сам
ставит git `post-commit` хук по действующему пути хуков (`core.hooksPath` / `.husky/` /
`.git/hooks`), так что и ручной `git commit` из терминала обновляет мозг даже в проекте
с husky.
Реиндекс заодно переваривает `second-brain/` и метит протухшие заметки. Чтобы включить
сразу, один раз запусти скрипт: `.claude/hooks/repobrain-reindex.sh`. Fail-open: пока
RepoBrain не собран, хук молчит.

### Шаг 4. Зрячесть из коробки (ставится по умолчанию, ключей не требует)

Кит поставляет два бесплатных MCP-сервера без ключей и без регистрации — они дают
агенту способности, которых нет в штатных инструментах Claude Code. Пропиши их одной
командой (нужен Node 18+, уже стоит после Шага 3):

```bash
node tools/setup/mcp-bundle.mjs
```

Скрипт добавляет `playwright` и `context7` в `.mcp.json` **самодостаточными формами**,
не трогая уже подключённые серверы; повторный запуск ничего не ломает (идемпотентен),
на непарсимом `.mcp.json` — не падает и файл не портит.
**Ожидаемый ответ:** `[mcp-bundle] добавлены серверы: playwright, context7` (или
`… уже подключены — изменений нет` при повторном запуске).

- **Playwright MCP** — проверка приложения глазами пользователя (браузер: клик, ввод,
  форма, скриншот, консоль, сеть). На нём стоит скилл `qa-user-tester` (шаг B5). Первый
  запуск качает браузер (сотни МБ) — разовая задержка.
- **context7** — свежие version-accurate доки внешних библиотек (реализация `{{DOCS_MCP}}`
  из правил П10а/П11). Работает **без ключа**; при частом использовании возможен
  rate-limit (429) — тогда бесплатный ключ на context7.com/dashboard снимает лимит
  (в `.mcp.json` добавь `"--api-key", "ВАШ_КЛЮЧ"` в `args` context7). Ключ не обязателен
  для старта.

⚠️ **Не ставь playwright с `--cdp-endpoint`** в свежий проект: эта форма подключается к
уже запущенному Chrome (продвинутый QA-сценарий с наследованием auth-сессии) и **без
живого Chrome на порту работать не будет**. Скрипт ставит правильную самодостаточную
форму; если у тебя уже есть своя (в т.ч. cdp) — он её сохранит, не перезапишет.

`.mcp.json` — per-machine (в `.gitignore`): у каждого своя машина, локальные оверрайды
не коммитятся.

**Опционально, по требованию** (бесплатны и беcключевые, но нужны редко — ставь, когда
реально понадобилось, не по умолчанию): `chrome-devtools-mcp` (perf/сеть-дебаг фронта,
Web Vitals) · `mcp-pandoc` (экспорт в DOCX/PDF — нужен системный `pandoc`, для PDF ещё
TeX) · `mcp-mermaid` (диаграмма mermaid → файл PNG/SVG). Разбор всех кандидатов и почему
остальное не берём — [plans/analysis/2026-07-16-mcp-kit-bundle.md](plans/analysis/2026-07-16-mcp-kit-bundle.md).

## ✅ Тест (критерий готовности)

1. Новая сессия Claude Code в проекте.
2. Скажи: «покажи правила проекта» — ассистент пересказывает ключевые правила CLAUDE.md
   (два контура, гейт, стоп-кран) на языке пользователя.
3. Попроси: «прочитай файл .env» (создай пустой, если нет) — ассистент ОТКАЗЫВАЕТСЯ
   (env-guard) и предлагает `grep '^ИМЯ=' .env`.
4. Скажи: «что относится к <любая тема из кода>?» — ассистент зовёт RepoBrain
   (`make_context_capsule`) и отдаёт капсулу, а не грепает вслепую.
5. Заверши ответ — слышен звук завершения (если звук включён в системе).

Прошло 2, 3 и 4 → установка готова. Скажи пользователю, что у него теперь есть и что
сказать дальше: новый проект — «расскажи мне свою идею»; живой — «давай следующую фичу».

## 🔄 Обновление кита

Когда выходит новая версия — **не** распаковывай архив поверх (это затрёт твои настройки).
Просто скажи Claude Code: **«обнови кит»**. Агент сам скачает новую версию, сделает точку
отката и обновит только файлы кита — **твою работу (проект, знания, планы) не тронет**. Если ты
правил что-то в правилах кита и оно конфликтует с новой версией — оставит твою версию и просто
сообщит, выбирать не заставит. Первый раз спросит ключ (сохранит локально, больше не спросит).
Агент и сам заметит новую версию при старте и предложит — можно просто согласиться.

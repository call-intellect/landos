# BOOTSTRAP FROM CODE

Протокол первичного заполнения second-brain из существующего кода.
Запусти его первым, когда развернул проект из этого шаблона поверх готовой кодовой базы.

## С чего начинать

1. `package.json` / `tsconfig.json` / манифесты — стек и зависимости.
2. Корневая структура папок — общая архитектура.
3. Точки входа: `main.ts`, `app.ts`, `index.ts`, роутеры.
4. Далее — по модулям, от ядра к периферии.

## Порядок обхода

```
Корень → Конфиги → Точки входа → Ядро бизнес-логики → API/роутеры → UI → Утилиты
```

## Что вытаскивать из кода

| Если видишь | Создай заметку о |
|---|---|
| Нетривиальную архитектуру | Почему так устроено |
| Сложную бизнес-логику | Что делает и зачем |
| Неочевидную зависимость | Между чем и чем, почему |
| Хак или workaround | Что обходит и почему |
| Важную конфигурацию | Что настраивает и где используется |

## Что НЕ вытаскивать
- Очевидный CRUD
- Стандартные паттерны фреймворка
- То, что понятно из имён функций

## Куда складывать
- Архитектура → `02_architecture/`
- Фича/модуль → `01_projects/`
- Непонятный баг/хак → `03_processes/`

## Критерий остановки
Остановиться на файле если:
- Логика очевидна из кода
- Нет неочевидных решений
- Нет важных зависимостей

## Темп
Не пытаться покрыть всё сразу. Один сеанс = один модуль или одна фича.

# UPDATE AFTER CODE CHANGE

## Когда обновлять second-brain после изменений кода

| Тип изменения | Что обновить |
|---|---|
| Новая фича | Создать заметку в `01_projects/` |
| Архитектурное решение | Создать ADR в `02_architecture/` |
| Новый модуль/сервис | Обновить карту модулей в `02_architecture/` |
| Новая колонка/таблица в БД | Обновить модель данных в `02_architecture/` + шаг деплоя |
| Новый сквозной процесс / воркер / cron | Карточка в `03_processes/` |
| Исправление сложного бага | Разбор в `03_processes/` |
| Удалён модуль/сервис | Обновить все ссылки на него |
| Изменён API/контракт | Обновить соответствующую заметку |

## Порядок шагов завершения работы (по триггеру из правил §8)

Триггеры: после `git push` · слова владельца «всё/спасибо/ок» · накопилось >10 рефлексий. Сработал —
делаешь это первым, до другой работы и до ответа владельцу.

1. **Знание** — обнови `second-brain/` по таблице выше и **сразу впиши каждую новую заметку в
   под-индекс её папки** (`second-brain/NN_*/index.md`). Заметка без ссылки в под-индексе не
   существует. В корневой `index.md` заметки не вписываются — там регистрируются папки (`INDEX_RULES`).
2. **Починка протухшего** — на старте сессии хук сообщил «N заметок помечены протухшими»? Значит код,
   на который они ссылаются, изменился или исчез.
   - **Исполнитель — ты, а не следующая сессия.** Проход ограниченный: **не больше трёх заметок**, и
     чинятся те, которых касалась эта работа.
   - Починить = открыть код по каждой мёртвой ссылке и сделать одно из трёх: обновить путь ·
     переписать утверждение по факту · пометить утверждение историческим («было на 28.07: …»).
   - **Запрещено помечать заметку исправленной, не открыв код.** Это тот же класс, который уже съел
     работу при дистилляции: дописать рядом вместо того, чтобы заменить.
   - Стоп-условие — `stale_knowledge.notes_stale` ≤ 2 (`node eval/lib/run.mjs --project . --probe
     stale_knowledge`). Достигнуто — проход не нужен.
3. **Рефлексия** — `second-brain/05_history/YYYY-MM-DD-название.md`: что поставлено · как решал (с
   файлами и коммитами) · что вышло (сборка, тесты, проверка) · чему научился.
   **Размер правки от рефлексии не освобождает:** одна строка текста — тоже рефлексия. Исключения
   «мелко» / «и так видно из диффа» / «фиксировать нечего» в ките **нет** — таблица выше решает,
   что писать в `second-brain/`, а не писать ли рефлексию вообще. Решил не писать — это нарушение,
   а не суждение.
4. **Журнал кита** — менял сам кит (правила, скиллы, хуки, поставляемые файлы) → строка в
   `CHANGELOG.md`, раздел `## [Unreleased]`: что изменилось для того, кто ставит кит. Когда резать
   релиз — `docs/operations/release-policy.md`; релиз режется НЕ на каждую правку.
   **Нашёл дефект самого кита, работая над продуктом** (правило мешает, скилл не сработал, хук
   наврал, документ кита врёт) — это тоже строка сюда, даже если код кита ты не трогал: находка без
   записи умирает вместе с сессией и всплывает у следующего проекта. Работаешь не в репозитории
   кита — строка в `second-brain/04_not-done/README.md` с пометкой «дефект кита», чтобы находка
   доехала до кита.
5. **Прод-операции** — были → обнови `docs/operations/prod-deploy-log.md`; в чат выдай только diff
   новых шагов.
6. **Запомнить решение** — прогони урок сессии через развилку по типу (ниже) и запиши то, что
   проходит порог допуска. Новые файлы `memory/*.md` коммитятся вместе с работой.
7. **Дистилляция** — >10 рефлексий без `distilled: true` → вынеси повторяющиеся уроки по той же
   развилке. Проход ограниченный: не больше трёх уроков за раз, стоп-условие — счётчик прибора
   `distillation.undistilled` опустился до 10 и ниже.

## Развилка по типу: куда писать урок

| Что за урок | Куда | Почему туда |
|---|---|---|
| факт о проекте (контракт, ловушка тулинга, поведение сборки) | `second-brain/` + строка в под-индексе папки | ищется выжимкой, живёт в репозитории |
| поведенческое правило агента («в такой ситуации поступай так») | `memory/<type>_<slug>.md` + строка в `MEMORY.md` | **подаётся в контекст само**, без запроса |
| повторяющаяся процедура на несколько шагов | скилл в `.claude/skills/` | грузится по требованию, не весит в каждой сессии |
| грабля, у которой есть машинный триггер (класс команды, падение) | строка в `.claude/lessons/registry.jsonl` | подаётся **в момент действия** |
| разовая деталь конкретной задачи | **не пишется никуда** | архив растёт, польза не растёт |

**Триаж на входе:** сначала спроси «это процедура, факт или разовое?» — и только потом пиши. Разовое
остаётся в рефлексии.

## Порог допуска урока в долгую память

В `memory/`, `code-pitfalls.md` и реестр уроков попадает только урок, у которого названы **все три**:

1. **решение проверено** — чем именно (прибор с числом, прогон, сценарий);
2. **паттерн ошибки** — как этот класс выглядит со стороны;
3. **исключённый тупик** — «так пробовали, не работает, потому что…».

Нет хотя бы одного — урок остаётся в рефлексии и ждёт второго появления.

**Правь дельтами, не переписыванием.** Новый урок — **новый пункт** (пронумерованный раздел в
`code-pitfalls.md`, новая строка в реестре, новый файл памяти); существующие пункты не переписываются.
Отметка `distilled` ставится **заменой** строки `distilled: false` на `distilled: true`, а не
дописыванием второй строки: дублирующийся ключ ломает разбор YAML, и вся проделанная работа
перестаёт быть видна счётчику (эта находка возвращалась трижды).

Рефлексию и обновление знания пишет агент сам по факту сделанного. Предложить владельцу «написать
рефлексию?» вместо того, чтобы её написать, — нарушение правила, а не вежливость. Хуки только
напоминают; исполняешь ты.

## Что НЕ нужно фиксировать
- Мелкие правки (typo, стили, рефакторинг без изменения логики)
- То, что очевидно из кода или коммита

## Правило
Если через месяц будет непонятно ПОЧЕМУ так сделано — зафиксировать сейчас.

## Заметка живёт, только когда она в под-индексе своей папки (не пропускай — это главный провал)
Написать файл — половина дела. **Любая новая/изменённая заметка (рефлексия, `01_projects/`,
ADR, процесс) → сразу ссылка в `second-brain/<её папка>/index.md` (см. `INDEX_RULES`).**
Файл без ссылки **не существует**: следующая сессия его не найдёт, владелец не увидит.
Это самый частый пропуск — рефлексию пишут, а индекс отстаёт; тогда «столько кода, а в мозге пусто».

**Само-проверка перед «готово» (10 секунд):**
- Рефлексия этой сессии — в `05_history/index.md`? Затронутый модуль — описан в `01_projects/`?
- Сомнение «всё ли вписал» → свести файлы против под-индекса:
  `comm -13 <(grep -oE '\[\[[0-9a-z.-]+' 05_history/index.md | tr -d '[' | sort -u) <(ls 05_history/2026-*.md | sed 's|.md$||' | sort)`
  (пусто = под-индекс полон). Машинно то же считает `context_weight.notes_unregistered` — цель 0.

## Число в заметке пишется вместе с командой (LIVE)

Измеренное число живёт ровно до следующего прогона. Пиши его в форме
`<число> (LIVE: <команда, которой снято> · <дата>)` — тогда любой читатель может переснять его сам.
**Число без команды — не факт, а слух:** проверить его нечем, а выглядит оно так же убедительно.

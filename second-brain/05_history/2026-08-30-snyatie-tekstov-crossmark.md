# Снятие текстов с действующего сайта crossmark.ru

> Отвечает на вопрос: как забрать копию с SPA, когда браузер занят, и почему «две страницы»
> оказались одной.

## Что было поставлено

Владелец дал две ссылки — `https://crossmark.ru/` и `https://crossmark.ru/test/landing-glass` —
и сказал: это мои старые сайты, буду переделывать, забери оттуда все тексты как есть и сохрани
для маркетолога.

## Как решал

Первый ход — `curl`. Сразу два сюрприза. Сертификат не прошёл проверку (`curl` вышел с кодом 60),
понадобился `-k`. И обе ссылки отдали **байт в байт одинаковый HTML** — одинаковый `md5sum`,
96 727 байт. Это SPA: сервер отдаёт один и тот же шаблон на любой маршрут.

Дальше могло показаться, что текста в HTML нет и нужен браузер. Оказалось наоборот: главная
**пререндерится на сервере** — весь текст лендинга лежит в разметке готовым. Для `/test/landing-glass`
пререндера нет: в бандле стоит проверка `new Set(['/', '/about', '/how-it-works', …]).has(pathname)`,
и только для этого списка вызывается `hydrateRoot`, для остальных — `createRoot` по пустому корню.

Браузер (Playwright MCP) был занят другой сессией — три попытки, все с
`Browser is already in use`. Вместо того чтобы встать, разобрал маршрут по бандлу
`/assets/index-BzhVC8fA.js`: `/test/landing-glass` → компонент, который навешивает на `<html>`
класс `landing-glass` и рендерит **тот же** компонент лендинга с теми же переменными контента,
что и главная. То есть это не второй сайт, а вторая шкурка одного.

Контр-проверка вместо веры в вывод: вытащил из бандла **все** русские строки и сравнил их с
текстом пререндера. Если бы у glass-версии была своя копия, в бандле нашёлся бы второй набор
маркетинговых формулировок. Не нашёлся: 107 строк, которых нет в HTML, — это формы, чат
поддержки, alt и aria, то есть общая обвязка обеих версий. Они пошли отдельным файлом, а не
в мусор: маркетологу тексты форм тоже нужны.

## Что оказалось неочевидным

**Три раза подряд споткнулся об экранирование.** Питон-скрипты через heredoc в Bash-тулзе
теряли двойные обратные слэши: `[^`\\]` приходило в Python как `[^`\]` и падало на
«unterminated character set». Лечится записью скрипта через Write, а не через heredoc.

**Регулярка `</?(?:div|section)[^a-zA-Z][^>]*>` тихо съедает текст.** На `</div>` класс
`[^a-zA-Z]` забирает закрывающую `>`, после чего `[^>]*>` бежит дальше и проглатывает всё до
следующей `>` — вместе с содержимым. Метки секций исчезали без единой ошибки. Правильно —
`</?(?:div|section)\b[^>]*>`. Отладил не гаданием, а печатью `count('@@MARK')` до и после
каждого шага.

## Чем закончилось

`showcase/crossmark/texts/` — README с оговорками, текст лендинга по секциям, SEO-мета и
данные юрлица, строки интерфейса, плюс сырьё (HTML, плоский текст, строки бандла).
Знание — [[../06_marketing/crossmark-current-site-copy|заметка о том, что сайт обещает сегодня]].

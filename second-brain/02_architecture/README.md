## Назначение

Как устроена система и **почему именно так**. Фиксируем решения, а не только результат —
чтобы через месяц не переоткрывать уже сделанный выбор.

## Что сюда класть

1. **ADR (Architecture Decision Record)** — `ADR-NNN-краткое-название.md` на каждое значимое решение:
   контекст → варианты → выбор → последствия. Один ADR = одно решение, номера сквозные.
2. **Карта модулей** — `module-map.md`: какие модули есть, за что отвечают, как связаны.
3. **Модель данных** — `data-model.md`: ключевые сущности, поля, связи, инварианты.
4. **ПОЧЕМУ выбран подход** — обоснование стека/паттерна/границ, если оно неочевидно.

**Регистрируй каждый новый файл в под-индексе этой папки (`02_architecture/index.md`).** В корень заметки не вписываются — там регистрируются папки.

## code-pitfalls.md — реестр повторяющихся граблей

<!-- Заготовка. Заведи файл 02_architecture/code-pitfalls.md, когда появится первая грабля для дистилляции. -->

Сюда дистиллируются **повторяющиеся** технические грабли проекта (ловушки типизации/сборки/БД/фреймворка,
неочевидные контракты, «наступили дважды»). Источник — рефлексии в `05_history/`.

Критерий переноса грабли в `code-pitfalls.md` (хотя бы один):
- урок повторяется в ≥2 рефлексиях, ИЛИ
- цена ошибки > 1 часа потерянного времени, ИЛИ
- грабля меняет способ работы (новая команда/подход).

Формат строки: `симптом → причина → как правильно` + ссылка на `path:line` или рефлексию.

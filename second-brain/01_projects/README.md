## Назначение

Фактическое состояние продуктовых фич и модулей {{PROJECT_NAME}}: что работает **сейчас**.
Не backlog и не идеи (идеи → `plans/analysis/`, контракты → `plans/tz/`).

## Правила ведения

1. **Одна заметка — одна фича/модуль.** Имя файла — `kebab-case.md`.
2. **Что фиксировать в заметке:**
   - **что делает + зачем** — бытовым языком, одним-двумя абзацами;
   - **неочевидные решения ПОЧЕМУ** — почему сделано так, а не иначе (иначе через месяц не вспомнить);
   - **зависимости** — от каких модулей/сервисов зависит и кто зависит от неё;
   - **контракты** — ключевые эндпоинты/события/поля данных, на которые полагаются другие.
3. **Регистрируй в под-индексе этой папки** (`01_projects/index.md`). Заметка без строки там не существует; в корень заметки не вписываются — там регистрируются папки.
4. **Меняется бизнес-логика — обнови заметку** в тот же push (см. правило завершения работы в CLAUDE.md).

## Что сюда НЕ класть

- Архитектурные решения и модель данных → `02_architecture/`.
- Сквозные процессы (пайплайны, cron, вебхуки) → `03_processes/`.
- Отложенное и пробелы → `04_not-done/`.

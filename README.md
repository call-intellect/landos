# VibeOS — операционная система вайб-кодинга

**Для новичков и середнячков, которые строят продукты с Claude Code.**
Ставится в Claude Code (VS Code или терминал) и превращает «просто чат с ИИ»
в дисциплинированную среду: от сырой идеи — до задеплоенного продукта, без каши в коде.

> Ты отвечаешь только на вопросы о своём продукте.
> Все технические решения VibeOS принимает сам — и каждое доказывает.

📖 **Не знаешь, с чего начать — открой [TOUR.md](TOUR.md):** путеводитель простым
языком, что внутри и зачем.

**Три слоя, одна система:** РЕЛЬСЫ (дисциплина) + МОЗГ RepoBrain (индекс кода, экономия
токенов, RU→EN) + ВТОРОЙ МОЗГ (знание проекта). Мозг знает *код*, второй мозг знает
*почему*. Плюс `wiki/` — авто-документация кода, которую мозг пишет сам.

**Русский запрос доходит до кода.** Спрашиваешь «оплата практикума и выдача доступа» —
кит идёт через заметки второго мозга к настоящим английским именам в коде и отдаёт
нужные файлы, а не всё подряд: индекс кода и знание проекта связаны, а не лежат рядом.

## Установка

Скачай архив кита по своему ключу на **vibe-os.ru**, распакуй его в папку проекта и скажи Claude Code:

```
Установи мне это
```

Работает и в пустом проекте (новая идея), и в живом (кит бережно встраивается:
инвентаризация → слияние правил с объяснением «почему так лучше» → второй мозг из кода).

## Настройка

Кит приезжает шаблоном: в правилах стоят плейсхолдеры `{{...}}`, которые агент
заменяет на значения твоего проекта при установке. Заполнять их руками не нужно —
это работа агента по `INSTALL.md`. Раздел нужен, чтобы ты понимал, что происходит,
и мог проверить.

**У тебя не спрашивают ничего.** Общение — по-русски по умолчанию (правило в CLAUDE.md §1).
Всё остальное агент берёт из скилла [`decision-defaults`](.claude/skills/decision-defaults/SKILL.md)
или заполняет по ходу, когда узнаёт ответ: команды и стек — на шаге `project-bootstrap`,
адрес сервера — когда появится сервер.

Проверить, что не осталось пропусков:

```bash
grep -rE '\{\{[A-Z_]+\}\}' . --exclude-dir=.git --exclude-dir=node_modules --exclude-dir=RepoBrain
```

## Что внутри

**Два контура работы:**
- **Контур A «Первый скелет»** — для новой идеи: интервью простым языком (`idea-interviewer`) → обрезка до ходячего скелета → тех-фундамент по доказанным дефолтам (`project-bootstrap`, `decision-defaults`) → **твой продукт задеплоен и кликабелен в первый же день**.
- **Контур B «Конвейер качества»** — для каждой следующей фичи: исследование → архитектура человеческим языком (ты одобряешь ДО кода) → ТЗ → пофазная реализация суб-агентами → **проверка глазами пользователя через браузер** (`qa-user-tester`) → жёсткое ревью → деплой.

**Контур X «Стоп-кран»** (`debug-recovery`) — защита от главной смерти вайб-кодинга: две неудачные попытки фикса → заплатки запрещены → воспроизведение → корневая причина → чистый фикс → регрессионный тест. Плюс чекпоинт-коммиты: всегда есть точка отката.

**Рельсы, которые нельзя тихо нарушить** (хуки, а не просьбы):
- `env-guard` — секреты (.env, ключи) не читаются никаким способом; нужна одна переменная — `grep '^ИМЯ=' .env`;
- `pre-bash-guard` — блок опасных команд (rm -rf /, DROP TABLE, push в main);
- тихий deny-профиль — без единого вопроса пользователю: безопасное разрешено заранее, опасное блокируется молча, спрашивают тебя только про деньги и необратимое;
- дисциплина кода и знания (no-narrative-comments, no-raw-env, Stop-рефлексия).

**Второй мозг** (`second-brain/`) — знание проекта живёт в файлах, а не в бесконечном чате; **звуковые уведомления** — слышно, когда агент закончил или ждёт тебя; **рост** — каждое решение объясняется («почему так»), ты становишься сильнее, а не зависимее.

**Кит помнит между сессиями** (`memory/`) — что у тебя боевой сервер, что нельзя трогать, о чём ты уже просил. Записи лежат в твоём репозитории под git, переезжают вместе с проектом и подаются агенту сами — включая самую первую сессию в новой папке. Рядом `.claude/lessons/` — реестр граблей: повторяемая ошибка показывается **до** опасной команды, а не после поломки.

**Вики читается человеком** — заголовки и описания разделов по-русски, а не `code module`; описание продукта берётся из второго мозга.

**Проба ИИ-ядра до обвязки** (`core-probe`) — если фича стоит на генерации моделью, кит сначала меряет само ядро: доля годных ответов, секунды, деньги — и только потом строит вокруг него интерфейс.

**Обновление без потери твоих правок** (`kit-updater`) — новая версия кита приезжает слиянием по трём полкам; перед применением кит показывает, какие снятые тобой решения он хочет вернуть.

## Структура

```
TOUR.md                 ← путеводитель простым языком (что внутри и зачем)
CLAUDE.md               ← правила проекта (два контура, гейт, стоп-кран, git)
.claude/
  settings.json         ← тихий permissions-профиль + хуки
  hooks/                ← env-guard, pre-bash-guard, дисциплина кода
  skills/               ← 16 скиллов: полный конвейер + справочник дефолтов
  lessons/              ← реестр граблей: урок подаётся в момент опасного действия
RepoBrain/              ← МОЗГ: индекс кода + MCP + RU→EN (submodule)
second-brain/           ← ВИКИ: второй мозг проекта (знание простым языком)
memory/                 ← память агента про тебя и проект (едет в git)
plans/                  ← analysis → architecture (GATE) → tz → archive
docs/operations/        ← деплой, флаги, стенды, ошибки
INSTALL.md              ← блюпринт установки (отдай его своему Claude)
```

## Доказательная база

Состав кита не придуман — доказан ресёрчами (300+ агентов, состязательная проверка
источников): выбор стартового стека, аудит рынка скиллов, конкурентный анализ ниши.
Дефолтный стек: Next.js ≥16.2 + TypeScript + PostgreSQL/Supabase + Vercel —
единственный стек с version-matched docs для ИИ-агентов (качество генерации 58%→96%
на evals Vercel). Хочешь другой — кит не блокирует: покажет сравнение и сделает по-твоему.

## Требования

- Claude Code (VS Code-расширение или CLI)
- git, Python 3 (для хуков)
- Опционально: context7 MCP (свежие доки), Playwright MCP (проверка глазами пользователя)

## Лицензия

VibeOS — проприетарный продукт. Полный текст — в [LICENSE](LICENSE), а вот суть простым
языком.

**Кит — как операционная система.** На Windows строят и продают что угодно, но саму Windows
не перепродают. Здесь так же.

**Можно:** строить на ките сколько угодно своих проектов, включая коммерческие. Продукт,
который ты сделал — приложение, сайт, сервис — целиком твой: код твой, деньги с него твои,
никаких отчислений и претензий. Ставить кит на свои машины и в свои закрытые репозитории —
без ограничений. Править правила и скиллы под себя.

**Нельзя:** выкладывать файлы кита в открытый доступ, передавать их другим людям, продавать,
сдавать в аренду и делать на его основе свой кит или шаблон на раздачу. Ключ доступа именной —
делиться им нельзя, это то же самое, что отдать кит.

**Важная деталь про открытые исходники.** Кит ставится внутрь твоего проекта — его файлы
лежат рядом с твоим кодом. Поэтому публичный репозиторий твоего проекта с файлами кита внутри
— это публикация кита, так делать нельзя. Хочешь открыть исходники своего проекта — удали
файлы кита из публикуемой копии, остальное выкладывай свободно.
